# Security input

- **Security input craft**: for any parser, matcher or filter on untrusted strings, write a hostile-input table first (CR, CRLF, NEL, U+2028, userinfo delimiters, backslash, IPv6, empty label, over-long, whitespace, non-ASCII, case and decoration variants), validate before matching, fail closed, prefer a real parser to a hand-cut, and derive closed lists from the grammar. Bound every read of external input with `take(cap + 1)` and cap every loop driven by a remote reply with a named constant. Redact before truncating and test a secret straddling the cap. Route every field of one record through the same sanitiser and test one hostile value per field. Text forwarded under a trusted identity to an interpreter (markdown, mentions, issue refs, URLs) gets a character allowlist or is made inert, and tests cover every decoding layer (entities, percent, unicode). When wrapping an API whose output can be capped, read its truncation marker and fail closed. Bind client-supplied numbers into SQL only after a range check at the edge. Never run a privileged command on a path an unprivileged job can write; run it as the job's uid and use a std or openat-based recursive delete. When a config value selects a trusted principal, docs and install steps state the owner and non-writability it needs, and the task lists it as an acceptance item.
