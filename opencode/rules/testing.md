# Testing

- **Test craft**: general technique lives here, repo files hold only repo-specific facts. Write the test first and watch it fail on the old behaviour. After the fix, mutate each changed line on its own, never several at once, and confirm a test goes red; a survivor means add a seam and a test. Give every branch of a selection line (an index pick, a default operand) a case only that branch satisfies. Test seams are injected parameters, never environment variables readable in the shipped binary. Prefer wide timing bands and an outer timeout on process tests; never assert wall-clock margins under 10x. Put tests that spawn children and bind sockets in their own test binary on macOS. For a limit that crosses a wire contract, use one shared constant. Measure a limit in the unit its enforcer counts: test with input under the cap in the string's native length unit and over it in the enforced unit (bytes). Generate Unicode or other category sets from an authoritative source. Kill processes by pid, never by name pattern. Run cleanup before returning an error. Reset a backoff only after the work succeeds. Cap any server-supplied wait. Verify after the final edit, run the formatter first, and check for a clean `git status` and stray files after the commit. When a failure repeats, send a `researcher` for trusted sources before patching the instructions. Before encoding another tool's file format, read its parser or spec and round-trip through the real parser. Every poll on external state gets a deadline and a terminal condition per ambiguous state; after a kill request treat the ambiguous state as ended. A future awaited in `select!` must be cancel-safe and cheap to recreate: run long polls in a spawned task and await a channel or `JoinHandle`. Probe each sandbox directive against the real workload on a live host, one probe per directive. Run destructive startup steps only after winning the single-instance guard. A test double models every state the real service reports. Enforce an invariant in the type that relies on it (private fields, fallible constructor). For a both-or-neither field group, test all set, none set, each single field missing; write one negative test per required field. Test pinned values with the default-config shape (a relative path), not only the tempdir shape. Test an error path by injecting the error, never by racing the kernel. Bound the reader of a child's output and abort it after the child exits, since a detached descendant can hold the pipe. When a commit changes a claim, grep the whole tree for the old wording and fix every hit. When a change touches a process-spawn path, run every test binary that spawns it. Test duplicate-key rejection at every nesting level and in every map-typed field. Test every limit with a shrunk value and an input just over it on the success path. A negative test must fail when the check it names is deleted: use inputs every other layer accepts, assert the exact refusal reason, and assert the guarded side effect did not happen. Give every probe a positive control and fail when its precondition is absent. Test an ordering fix by swapping the lines and requiring red. Tests of a lifecycle guard drive the real path (cancel, lost lease, shutdown, hang); a holder keyed by id clears on every fetch. A test that creates a named external resource uses a unique name, drops it via a guard, and runs twice. After fixing a flake class in one test file, grep its siblings. Test a security policy under its production setting with the real tool. Make path arguments absolute once at config resolution and test with a relative root. Before deleting a recovery path, list every actor that can leave the state it repairs; replace a directory by rename-aside then delete. A write-ahead record before a fallible await gets a drop guard that records the cancel. Share error-message constants and wire predicates in one crate both sides use, and test each normative spec sentence on every request path. When a poll returns no data keep the last good value. Check a manifest against the namespace quota and LimitRange. In create-then-delete scripts refuse an existing name and arm the delete trap (EXIT INT TERM) only after create succeeds. Check a doc claim about a third-party option against its man page.
